  2. Why the winners won

  - In Blackjack, at the chosen settings, all three updates are effectively 
    greedy, so the divergence doesn't matter.
    - Comparing steps at the uniform policy (how far one update moves it), KL at
      η=100, Euclidean at η=50 and Tsallis(3.5) at η=30 all jump to the best
      action under the latest Q estimate in one update.
    - That makes the method roughly policy iteration on a noisy Q estimate of
      about 260 observations, which is why the 11/9 split is identical for all
      three.
  - In GridWorld, Tsallis with q < 1 kept poor actions in play. The key detail
    is how TOMC treats rare actions:
    - Any action with π < (1−γ)/|A| = 0.025 is not estimated and gets the
      worst-case value of 10. SPMD then pushes it lower, so it never comes back.
    - KL suppresses a worse action by a factor of e^(−ηΔQ). After one update at
      η=100 the smallest action probability is about 1e−68.
    - Euclidean sets worse actions exactly to 0.
    - Tsallis with q=0.5 suppresses them only polynomially, about (ηΔQ)^(−2).
      After one update its smallest probability is 1.6e−3.
    - So near-tied actions stay in play and get re-estimated before the policy
      commits. Tsallis made fewer, better-informed updates (median 7 vs 27,
      using about 5× more observations each) and never fell into the dead-end
      policy that ruined seed 201.
  - Part of the gain is just a smaller step. At the uniform policy, Tsallis(0.5)
    at η=30 moves about as far as KL at η≈15, much less than the baseline's
    η=100.
    - In the old study, both winners also moved much less per update than KL did
      at η=25.
    - The step grids were not adjusted for how far each divergence moves the
      policy per update, so the divergence effect and the step-size effect are
      mixed together.
    - Weak evidence that the shape matters too: in tuning, KL at η=10 did worse
      than Tsallis(0.5) at η=30. That rests on only 3 seeds.

⏺ Nothing is wrong with the Euclidean update itself. With TOMC it ties KL, and
  the tests confirm it solves its update problem exactly. It breaks only in
  combination with True Online TD, because of how the TD estimator initializes
  Q.

  The cause: TD's zero start makes unsampled actions look best, and Euclidean 
  chases them.
  - The TD estimator restarts Q at q_init = 0 on every SPMD iteration
    (src/ie692_rl/enhancements/true_online_td/td.py, _TDEstimator).
  - GridWorld costs are all ≥ 0 and true Q values are around 2. So any action
    not sampled during an estimate's 50k steps keeps Q = 0, and looks like the
    cheapest action in its state. My instrumented runs showed this for every
    unsampled pair, under every divergence.
  - KL tolerates this. Its update multiplies probabilities, so a rarely-taken
    action can grow only by a bounded factor per step from a tiny base. It
    drifts up, gets sampled, and its Q gets corrected. In effect the zero start
    works as mild, cheap exploration.
  - Euclidean feeds on it. Its update subtracts η × Q from probabilities, then
    projects back onto the simplex.
    - The projection sets many actions exactly to zero, so those actions never
      get sampled.
    - The next estimate then gives them Q = 0, about 2 below everything else,
      and the additive update moves most of the state's probability onto them at
      once.
    - The next estimate samples them, finds they are worse, and now other
      actions have gone unsampled. The policy flips back and forth instead of
      converging.

⏺ No, none of the instruction documents mention it. I searched handout v3,
  handout v4 and the proposal. The handout only says to implement TOMC and a
  tuned SPMD, and to tune up to three parameters. The proposal writes TD's
  update rule but never says what Q starts at. So the zero start is an
  implementation choice. It came from the team's original TD code
  (policy_eval_td_enhanements/td.py at commit c09fc3e, theta = np.zeros(...)),
  and the refactor kept it as the default q_init = 0.0. Starting at zero is also
  the usual default in the textbooks (Sutton & Barto; van Seijen & Sutton), so
  nobody chose it on purpose.

  What "start Q at 0" means here. Each SPMD iteration asks the TD estimator for
  a Q table for the current policy π. The estimator does this:

  1. It creates a fresh table with Q(s, a) = q_init = 0 for every state–action
     pair. It does not reuse the previous iteration's table (np.full(n_features,
     q_init), td.py:358).
  2. It runs one stream of transitions (50,000 in GridWorld, 2,000 in
     Blackjack), choosing actions from π. Each step updates only the entry for
     the pair just visited (with Dutch traces, recently visited pairs too).
  3. It returns the table, and SPMD updates the policy using every entry,
     including ones that were never touched.

  A pair that wasn't visited in that stream therefore comes back with Q = 0,
  which is just the starting value, not an estimate. That happens when π(a|s) =
  0, which Euclidean produces often, when π(a|s) is tiny, or when the state
  isn't reached. Whether that's harmful depends on the cost scale:
  - GridWorld: costs are between 0 and 1 per step and true Q values are
    around 2. A 0 says "this action costs nothing", which is overly optimistic,
    so SPMD moves probability toward it. That is the Euclidean failure from my
    last answer.
  - Blackjack: costs are −1, 0 or +1 per hand. A 0 sits in the middle of the
    range, so it biases far less.

  TOMC handles the same situation explicitly. Pairs below its probability
  threshold get the worst-case value, cost_bound/(1−γ), which is 10 in GridWorld
  (core/tomc.py). So the two estimators make opposite assumptions about
  unsampled actions: TD treats them as free, TOMC as maximally expensive. That
  difference never appeared in the methods description. The "maximum-cost start"
  rerun gave TD the same convention as TOMC (estimator.q_init = 10 for
  GridWorld, 1 for Blackjack).

  For the report: state the start value as part of the TD method. Starting
  optimistically is a known exploration trick ("optimistic initial values",
  Sutton & Barto §2.6). It helps KL and Tsallis, which raise an action's
  probability only gradually, and breaks Euclidean, which can move a state's
  probability onto such an action in one step. Since nothing in the handout
  fixes it, you could also treat the start value as a tuned parameter, or carry
  Q over from the previous iteration so that no entry is ever just a
  placeholder.

  result: The handouts and proposal say nothing about initializing Q. "Start Q
  at 0" means the TD estimator begins every SPMD iteration with a fresh all-zero
  Q table and returns 0 for any pair it never visited, a default carried over
  from the team's original TD code.

  Why the Blackjack curves are so tight: the five TOMC-based methods (baseline,
  Euclidean, Tsallis, both entropy versions) end in exactly the same place on
  all 20 seeds. Each time, 11 seeds reach the optimum and 9 land on the same
  suboptimal policy (gap 0.194). So their mean curves are the same line at 9/20
  × 0.194 = 0.087, with nothing else in between. Three things cause it:
  - Tuning picked near-greedy settings. Tuning on Blackjack uses only 12k steps
    and 3 seeds, so a setting can score only 0, 0.065, 0.129 or 0.194, and many
    tie at 0. Ties break toward the largest step size, so every method ends up
    jumping straight to the best action under its latest noisy Q estimate.

    entropy weight barely changes the update. Every seed draws the same random
    samples, so all five methods follow the same trajectory.

    0.05 threshold, get the worst-case value, and never come back.
